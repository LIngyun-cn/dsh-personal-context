# 个人上下文 · dsh-personal-context

把长期对话记忆变成**用户自己拥有的 Markdown 文件**，而不是某个模型或平台的附属记忆。

插件安装在 DeepSeek Harness（DSH）里，提供左侧栏「个人上下文」入口，并在后台做四件事：

1. 从正常对话中识别有长期价值的信息；
2. 追加到分层 Markdown 记忆库，必要时更新稳定文档；
3. 新会话开始时按需注入一小段最相关的上下文；
4. 支持合并、归档、审计、备份、恢复、导出与迁移。

插件本身**不调用大模型、不联网**。规则负责兜底捕获，模型通过 `personal_context` 工具做语义判断；因此日常运行成本为零，也不会把记忆锁进某个模型的内部记忆。

---

## 1. 安装

要求 DSH `>= 0.2.2-rc.1`，Node `^22.19.0 || >=24.0.0`。插件是纯 ESM、无运行时依赖，不需要构建。

```powershell
git clone <repo-url> dsh-personal-context
```

安装方式（任选其一）：

- 在 DSH 的「插件」页选择从本地目录安装，指向克隆下来的目录；
- 或让 DSH 里的 agent 执行 `plugin_manager install_bundle`，`target` 填该目录的绝对路径。

安装成功后：

- 左侧栏出现「个人上下文」；
- 系统提示词里出现个人上下文规则；
- agent 获得 `personal_context` 工具；
- 会话里可以使用 `/personal-context` 命令。

首次初始化会创建：

```text
C:\Users\<你>\.dsh\personal-context\
├── settings.json          # 配置
├── state.json             # 运行状态（错误、最近捕获时间）
└── Memory\                # 知识库，可整体搬走
    ├── README.md          # 管理协议
    ├── MASTER.md
    ├── INDEX.md
    ├── topics\general\
    │   ├── AGENTS.md
    │   ├── LOG.md
    │   └── archive\
    ├── reports\
    ├── backups\
    │   └── summaries\       # 过期备份的永久二级摘要
    ├── exports\
    └── archive\             # 历史会话全文（可选，见 2.6）
        ├── catalog.jsonl    # 会话索引
        ├── manifest.json
        └── txt\             # 每会话一份 Markdown 原文
```

`dataDir` 可以在面板「设置」里切换；切到已有的 `Memory` 目录即可完成迁移或导入。

## 2. 日常使用

### 2.1 侧栏面板

| 页签 | 能做什么 |
| --- | --- |
| 总览 | 看主题数、当前记录、备份、待整理数量；手动记一条；暂停/恢复；整理、审计、导出 |
| 主题 | 浏览主题的稳定概述、动态日志；编辑或删除单条记录；手动整理某主题 |
| 搜索 | 关键词检索（支持多词、日期格式互转），显示主题、性质、日期与摘要 |
| 档案 | 在已导入的历史会话中按标题/主题搜索；可勾选「全文检索」扫原文，点「读原文」查看前 30,000 字 |
| 设置 | 合并阈值、注入预算、备份保留、捕获灵敏度、自动捕获/自动注入开关、数据目录、备份恢复、导出/导入 |

标题栏的绿点表示正在记录。点「暂停记录」会立即停止自动捕获，但手动保存和工具写入仍然可用。

### 2.2 直接对话即可

不需要说「记住这个」。出现下面这类内容时，模型会主动调用工具保存，规则捕获作为兜底：

- 稳定事实：姓名、所在地、职业、设备、长期项目；
- 偏好：喜欢/不喜欢、交流与工作习惯；
- 决定：选定方案、放弃方案、截止日期、约束；
- 目标与项目进展；
- 明确说出的「记住……」。
- 模型自己的推测只能标为 `inference`，不会被写成用户事实。

普通闲聊、临时情绪、一次性任务细节、代码片段、密码/密钥/验证码/证件号不会进入记忆。

### 2.3 新会话先选上下文

点「新会话」后，输入框上方右侧有一个「记忆」按钮。可以先选这次会话要加载什么，再开始说第一句话：

| 选项 | 注入内容 |
| --- | --- |
| 不加载 | 完全不注入；这一轮对话从零开始，适合临时任务 |
| 摘要 | `MASTER` 稳定摘要 + 主题索引（默认，最省 Token） |
| 按主题 | `MASTER` + 勾选主题的稳定概述（可多选） |
| 最近记录 | `MASTER` + 最近 12 条动态日志 |

选择只对当前会话生效，不会写入长期文档，也不改变其他会话。选完后按钮会显示当前选择；不选则仍按「摘要」处理。注入内容作为该会话的系统提示存在，后续轮次仍可见，受「注入预算」限制。

这个选择在第一条消息之前也能生效：插件用每个 agent 自己的动态提示词段读取选择，不依赖命令通道（新会话尚未启动命令）。

### 2.4 斜杠命令

在任意会话里：

```text
/personal-context status
/personal-context search 部署 日期
/personal-context save 2026-11-17 决定采用方案 B
/personal-context {"action":"save","text":"2026-11-17 决定采用方案 B","kind":"decision","topic":"general"}
/personal-context {"action":"merge","force":true}
```

只给动作名和文本即可；需要 `kind`、`topic`、`force` 等字段时再用 JSON。返回值为 JSON。面板 UI 也走同一个命令通道，所以**面板操作需要当前有一个打开的会话**；没有会话时面板会提示先打开对话。

### 2.5 让 agent 使用

系统提示词会要求模型：

- 回答涉及用户背景、偏好、既定决定、项目历史的问题前，先 `search` 或 `context`；
- 出现长期有价值的新信息时 `save`，每条带日期与来源；
- 区分 `fact / preference / decision / opinion / idea / question / inference`；
- 冲突不覆盖，追加新记录并说明「此前为……」；
- 工具失败时明确说「未保存成功」。

工具动作：

| action | 用途 |
| --- | --- |
| `status` / `overview` | 运行状态、统计、最近记录 |
| `context` | 取 MASTER 摘要 + 主题索引，可带 `query` 和 `budget` |
| `search` | 跨主题关键词检索，`query`、`limit` |
| `topics` / `topic` | 主题列表 / 单个主题详情（`id`） |
| `save` | 保存记录：`text`、`kind`、`confidence`、`topic`、`title`、`source` |
| `update` / `delete` | 按记录 `id` 修改或删除（删除会归档原文） |
| `merge` | 整理：`topic` 可选，`force` 忽略阈值 |
| `audit` | 生成审计报告 |
| `export` | 导出整库 |
| `backups` / `restore` | 备份列表 / 按 `id` 恢复 |
| `doc` | 读取 `master`、`index`、`readme`、`topic:<id>:agents|log` |
| `configure` | 修改配置（见下） |
| `archive` | 检索历史会话档案：`query`、`limit`、`deep`（全文扫描较慢） |
| `archive_doc` | 按会话 `id` 前缀读取档案原文（最多 30,000 字） |

### 2.6 历史会话档案（可选）

只靠摘录式 LOG，旧对话里的具体细节会丢。档案层把**每个历史会话的原文**作为只读资料挂进知识库，需要时再检索，不占日常注入预算。

档案导入是通用的，期望数据目录下存在：

```text
dataset/
├── sessions.jsonl      # 每行一个会话：session_id / title / inserted_at / message_count / chars
├── txt/<id>.md         # 每个会话一份 Markdown 原文
└── INDEX.md            # 可选：表格里的 [txt](...) 链接用来映射 id -> 主题
```

导入命令：

```powershell
node scripts/import-archive.mjs `
  --source .\data `
  --home $HOME\.dsh\personal-context `
  --seed .\my-seed.json
```

参数：

- `--source`：包含 `dataset/` 的目录；
- `--home`：插件控制目录（`settings.json` 与 `Memory/` 所在处）；
- `--seed`：可选的整理层种子 JSON；不传则只导入档案，不生成 `MASTER.md` 和主题；
- `--dry-run`：只打印会话数、主题数与复制目标，不写文件。

种子格式见 [`scripts/seed.example.json`](scripts/seed.example.json)：`master` 写稳定画像，`topics` 写主题背景、当前状态、结论、待办和带日期的条目。导入会**合并**已有主题日志，不覆盖旧记录。

日常对话里，模型可先 `search` 摘要记忆；不够时用 `archive` 找会话，再 `archive_doc` 读原文。面板「档案」页也提供同样能力。全文检索是逐文件扫描，默认关闭。

## 3. 配置

配置文件：`~/.dsh/personal-context/settings.json`。面板与 `configure` 都会写这里，并做范围校验。

| 键 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `dataDir` | `~/.dsh/personal-context/Memory` | 绝对路径 | 知识库根目录；切换即迁移 |
| `mergeThreshold` | `40` | 5–500 | LOG 达到多少条时提示整理 |
| `injectBudget` | `1200` | 200–8000 | 新会话注入的最大字符数 |
| `retention` | `120` | 20–500 | 原始备份保留份数上限 |
| `retentionDays` | `180` | 30–3650 | 原始备份精确保留天数；超期先写二级摘要再删除 |
| `minScore` | `2` | 1–10 | 规则捕获灵敏度，越高越保守 |
| `autoCapture` | `true` | 布尔 | 是否后台自动捕获 |
| `autoInject` | `true` | 布尔 | 新会话是否自动注入摘要 |
| `autoMerge` | `true` | 布尔 | 达到阈值后是否在保存后自动整理（先备份） |
| `autoAudit` | `true` | 布尔 | 启动时距上次审计 ≥30 天是否自动审计 |
| `paused` | `false` | 布尔 | 全局暂停自动捕获 |

示例：

```json
{
  "mergeThreshold": 40,
  "injectBudget": 1200,
  "retention": 120,
  "retentionDays": 180,
  "minScore": 2,
  "autoCapture": true,
  "autoInject": true,
  "autoMerge": true,
  "autoAudit": true,
  "paused": false
}
```

## 4. 文档协议（可直接手改）

所有记忆都是普通 Markdown。机器字段放在 HTML 注释里，正文可自由编辑；只要保留注释，插件仍能解析。

`LOG.md` 的一条记录：

```markdown
### [decision] 采用方案 B

2026-11-17 决定采用方案 B，因为部署更简单；此前考虑过方案 A。

记录时间：2026-11-17T14:02:11.000Z　来源：session:65a8c3f5/turn:3　性质：决定　置信度：high
<!-- pc:entry {"id":"e_xxx","kind":"decision","title":"采用方案 B","at":"2026-11-17T14:02:11.000Z","source":"session:65a8c3f5/turn:3","by":"model","confidence":"high","status":"current","sensitivity":"normal","hash":"..."} -->
```

- `MASTER.md` 只做有依据的追加，保存相对稳定的画像；不覆盖旧内容。
- `AGENTS.md` 是主题的稳定概述：背景、当前状态、重要结论、待解决、历史。主题元数据带 `sensitivity`。
- `INDEX.md` 是主题索引：id、标题、路径、条目数、归档数、敏感度、关键词、更新时间。
- `archive/` 保存合并后的旧日志与已删除条目。
- `reports/` 保存审计报告；`backups/` 保存写入前快照，`backups/summaries/` 保存过期备份的永久二级摘要。

### 敏感度标记

- 三级：`normal` / `important` / `sensitive`，写在 `AGENTS.md` 与 `INDEX.md` 的机器字段里；单条记录可覆盖主题默认值。
- 默认：健康、家庭与情绪、兴趣与消费为 `sensitive`；与 AI 的关系为 `important`；其余为 `normal`。
- 面板会在主题列表、主题详情、最近记录和搜索结果里显示「敏感 / 重要」角标。
- 敏感度**只影响展示**，不会改变自动注入内容；旧记录不会被批量改写或删除。需要更严格的隔离时，仍应使用「不加载」或按主题选择。

完整协议在知识库的 `README.md` 里，会随库一起迁移。

## 5. 合并、审计、备份、迁移

### 合并（高频追加、低频改写）

- 默认 LOG 达到 40 条时提示整理；面板「整理所有达标主题」按阈值执行，主题页可强制整理。
- `autoMerge` 开启时，达到阈值的那次保存结束后会自动整理该主题（先备份，再归档、重写 AGENTS、清空 LOG）。关闭它则只提示，由你手动触发。
- 合并时先把完整旧日志归档到 `topics/<id>/archive/LOG-<日期>-<序号>.md`，再用确定性规则重建 `AGENTS.md`，最后清空 LOG 并更新 INDEX。
- `MASTER.md` 不参与合并重写，只在有高置信度画像信息时追加。

### 审计

`autoAudit` 开启时，插件启动会检查距上次审计是否已满 30 天；满足则自动跑一次（只写报告，不改记忆）。也可随时手动审计。

生成 `reports/audit-<日期>-<序号>.md`，检查：
- 完全重复的记录；
- 超过 180 天仍标记为 `current` 的记录；
- 相似但肯定/否定表述相反的潜在冲突；
- INDEX 与目录不一致。

审计**不会自动改写**任何记忆；冲突需要用户判断。

### 备份与恢复

- 每次写入前自动快照，默认保留 **120 份**、**180 天**；面板「备份」列出时间和标签，可在窗口内一键精确恢复。
- 超过 180 天或超出份数上限的原始备份会先写一份确定性二级摘要到 `backups/summaries/YYYY-MM.md`（备份 id、时间、标签、文件哈希、日志条目标题与 id），**确认写入成功后才删除原始目录**。摘要永久保留。
- 180 天以外的备份只能查摘要，不能逐字节恢复；这避免了备份无限增长。
- 恢复前会先给当前状态再做一份 `pre-restore` 备份，避免恢复本身造成不可逆损失。
- 也可直接把 `backups/<id>/files/` 下的文件复制回知识库。

### 导出、导入、迁移

- 导出：`exports/personal-context-<时间戳>/`，包含整库与 `manifest.json`。
- 导入：把一份含 `MASTER.md` 的目录复制进 `imports/`，再在设置里把 `dataDir` 指过去；或者直接手动替换 `Memory`。
- 迁移：整个 `Memory` 目录可以复制到另一台机器、另一个模型或另一个平台；不依赖 DSH 专有格式。

### 版本与恢复

每条记录带 `记录时间`；修改会写 `editedAt`；删除会把原文移入 `archive/deleted-*.md`；合并保留完整归档。因此历史观点不会被静默覆盖。

## 6. 隐私与安全

- 默认只写本机文件，不发网络请求，不调用模型接口。
- `Memory` 与备份**不加密**；请自行保护用户目录与磁盘。
- 捕获规则会过滤常见秘密模式（密码、API key、私钥、身份证、银行卡、验证码、手机号），但这只是兜底，不能保证 100% 识别；敏感内容请勿写进对话。
- 文件写入使用同目录临时文件 + `fsync` + 原子重命名；写入关键文档前检查文件戳，冲突时返回「文件已被另一个窗口修改，请刷新后重试」。跨进程写入用 `Memory/.pc.lock` 串行化，进程崩溃后锁会在 30 秒内视为过期。
- 主题 id 只允许 `[a-zA-Z0-9_-]`，所有路径都做根目录包含检查。

## 7. 已知限制

- **没有会话结束钩子**。DSH 不提供 `turn/end` 之外的「会话关闭」事件，所以自动捕获在每轮 `turn/end` 落盘；如果应用在一轮中途被强制结束，该轮可能来不及捕获。
- 自动捕获只读**用户消息**，不读助手消息，避免把模型推测写成用户事实；助手侧的重要结论需要模型主动 `save`。
- 主题归类是确定性的（显式主题 → 工作区匹配 → 标题/关键词 → `general`）；没有向量语义检索，跨主题检索基于关键词、日期变体、相似度与时间衰减。
- 档案检索也是关键词/全文匹配，不做语义理解；`deep` 会扫全部原文，数据量越大越慢。
- 档案原文按 30,000 字截断显示；需要完整原文时直接打开 `archive/txt/<id>.md`。
- 档案是额外的只读文件，体积取决于导入量，会随 `Memory` 一起备份/导出/迁移；不需要时删除 `Memory/archive/` 即可。
- 面板的读写通过会话命令完成，因此**需要至少一个打开的会话**；纯离线浏览可直接打开 Markdown 文件。
- 新会话选择器依赖宿主的 `webServer` 服务与本机 JSON 路由；没有该服务时按钮仍显示，但保存会明确报错。路由使用同源校验和客户端标记，只允许本机同源页面读写「本会话加载什么」；它不是认证机制，本机其他进程仍可访问本地端口。
- 会话选择只影响当前会话，不会自动转成长期记录；需要沉淀的内容仍由模型 `save` 或手动保存。
- `MASTER.md` 是追加式，不做自动去重或改写；需要精简时请手动编辑。
- 单用户、本地单机设计；没有多用户权限、加密和云同步。

## 9. 卸载

1. 在「插件」里停用/移除 `dsh-personal-context`；
2. 记忆仍在 `~/.dsh/personal-context/Memory`，不会随插件删除；
3. 如需保留，先复制整个 `Memory` 目录。

## 10. 设计取舍

- **文件是产品，插件只是读写器**：所有派生结构都能从 Markdown 重建。
- **默认零模型成本**：规则捕获 + 模型工具写入，避免每轮调用小模型做抽取。
- **数据安全优先于自动化**：不覆盖、不硬删、先备份、冲突只报告；不确定时宁可少记。
- **追加优先**：日常只写 LOG，合并是显式/阈值触发的低频操作。
- **单一服务入口**：面板、命令、工具共用 `PersonalContextService`，避免三套逻辑漂移。
